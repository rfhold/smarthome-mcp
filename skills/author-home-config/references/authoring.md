# Authoring And Evidence

Use `home_assistant_query` for `scene.list`, `scene.get`, `automation.list`, `automation.get`, `automation.validate`, `automation.traces`, `blueprint.list`, and `blueprint.get`. Use `home_assistant_exec` for `scene.upsert`, `automation.upsert`, `blueprint.save`, and `automation.from_blueprint`. Read current schemas for exact fields and bounds; wrappers are closed, while bounded native objects preserve Home Assistant semantics.

Lists discover editor-managed config keys; YAML-only entries without safe stored IDs are omitted. Gets require `config_key` and return complete native objects, including potentially sensitive embedded values. Endpoint-wide `mcp:use` and the configured administrator token authorize these operations without an exposure lookup or recursive reference checks. Do not mistake this exception for permission to bypass a denied entity control.

Upserts require `config_key` and complete `config`. A present top-level `id` must be a string exactly matching the key. The service inserts or replaces the entire entry; it never reads, merges, or returns prior configuration. Preserve intended fields yourself. Acceptance means Home Assistant accepted a write for asynchronous reload, not that reload completed, triggers attached, a scene activated, or future execution will succeed. `scene.activate` is a separate exposure-gated control.

`automation.validate` validates submitted native trigger, condition, or action sections against current integrations. It does not read stored config or prove future conditions, templates, service availability, or execution. `automation.traces` accepts an exact `item_id` and returns bounded newest-first summaries of retained runs, not full traces, raw errors, config, variables, contexts, or service data. No traces does not prove failure to load or trigger; past success does not prove future success.

Blueprint actions support only automation blueprints and validated relative blueprint paths, never arbitrary files or URLs. `blueprint.get` needs the installed and set-up `smarthome_mcp` integration and returns semantic YAML, not byte-identical source: comments, style, and order can change. `blueprint.save` always replaces the selected path, never merges; preserve prior YAML privately if rollback matters. YAML and native JSON have 256 KiB bounds; native JSON depth is at most 32.

`automation.from_blueprint` takes a config key, blueprint path, and bounded native inputs. Native substitution preflight must succeed before writing a compact automation with `use_blueprint`; expanded preflight content is not persisted. No save or creation implies restart. Load `maintain-home-integration` if integration installation or setup is needed; those require separate decisions.

Keep config keys, source, inputs, references, complete configs, trace details, and upstream errors out of telemetry and unnecessary replies. There are no config deletes, generic service/script execution, full trace reads, blueprint imports/deletes, script blueprints, or generic config flows. Home Assistant internals are version-sensitive; local mocks establish bounds and routing, not live compatibility.
