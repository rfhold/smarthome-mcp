# Authoring And Evidence

Read `smarthome://scenes`, `smarthome://automations`, and `smarthome://blueprints`, then follow returned config and trace links. Use `query` action `automation.validate` for submitted fragments. Legacy list/get/upsert/save tools are not public. Catalogs contain at most 100 entries and are not a complete inventory. Config/blueprint item reads use the owning administrator boundary and validated canonical identifiers directly.

Catalogs discover editor-managed config keys; YAML-only entries without safe stored IDs are omitted. Config resources return complete native JSON, including potentially sensitive values, with deterministic pretty serialization. Endpoint-wide `mcp:use` and the administrator token authorize these operations without exposure lookup or recursive reference checks. This exception is not permission to bypass a denied control.

Create/edit are always discoverable and use existing native APIs without a Core patch or extra component commands. Check the schema and resource metadata. `_meta.revision` hashes the exact displayed semantic text; `_meta.concurrency: 'single-writer'` and `_meta.revision_check: 'best-effort'` are explicit limitations. No concurrent writer may change the configuration during authoring. These checks are observations, not atomic native preconditions.

`create` uses `{action, input}` with `scene.create` or `automation.create` input `{config_key, text}`, or `blueprint.create` input `{path, text}`. Supply complete native JSON object text or blueprint YAML, not a partial merge. Observed existing identifiers fail with `already_exists`. Native scene/automation POST is an upsert and could overwrite a concurrent writer after preflight; creation is not atomic create-only.

`edit` takes direct `{uri, expected_revision, edits}` arguments. Use 1 through 256 ordered replace or insert operations. Replace uses `{operation: 'replace', old_text, new_text}` with one unique nonempty match, including overlaps. Insert uses `{operation: 'insert', text, placement}`; start/end forbid anchor even null, before/after require one unique nonempty `anchor`. The wrapper reads fresh text, checks the digest, applies the whole sequence locally, validates bounds and JSON/YAML candidates, re-reads, and submits one native write. Failed sequences never write, but there is no native transaction. Text no-ops and JSON/YAML-semantic net-zero edits fail. Local YAML parsing requires one mapping document, rejects syntax errors and duplicate keys, and preserves `!input` tags. Native owners still validate their complete domain schemas before persistence. Do not invent or recompute a revision from reformatted text.

Persistence acknowledgment is not reload completion. Conflict requires a fresh read and a new decision. `mutation_outcome_unknown` is nonretryable: inspect before any further explicitly authorized mutation. Neither timeout nor cancellation proves rollback.

`automation.validate` checks submitted native trigger, condition, or action sections against current integrations, not future operation. Automation trace resources return bounded newest-first retained-run summaries, not full traces, raw errors, config, variables, contexts, or service data. No traces does not prove failure to load or trigger; past success does not prove future success.

Blueprint resources support only automation blueprints and validated relative paths, not arbitrary files or URLs. Reads require the installed and set-up `smarthome_mcp` integration and return semantic YAML, not byte-identical source: comments, style, and order can change. Blueprint slashes are percent-encoded in canonical links. YAML and native JSON have 256 KiB bounds; native JSON depth is at most 32.

Scene activation is a separate exposure-gated `execute` command. Acceptance, asynchronous reload, activation, and retained traces are distinct facts. Load `maintain-home-integration` when installation or setup is needed; each requires a separate decision and no configuration operation implies restart.

Keep config keys, source, inputs, references, complete configs, trace details, and upstream errors out of telemetry and unnecessary replies. There are no config deletes, generic service/script execution, full trace reads, blueprint imports/deletes, script blueprints, or generic config flows. Home Assistant internals are version-sensitive; local mocks establish bounds and routing, not live compatibility.
