# Home Assistant Shared Contract

Public tools are `create`, `edit`, `query`, and `execute`; current data uses dynamic resources. The [resource-first contract](resource-first.md) owns routing, templates, and single-writer authoring. Legacy names in domain documents refer to private adapters only. The [MCP Skills catalog](skills.md) supplies authored guidance, not authority. Generated help and legacy public tool aliases are absent. Input schemas reject unknown fields and existing semantic validation still precedes each adapter's network contact.

Each Home Assistant HTTP or WebSocket invocation acquires one of four non-waiting permits and has a 20-second end-to-end deadline. The deadline covers WebSocket authentication and commands, exposure authorization, REST response reading, validation, and output construction. URLs are limited to 8 KiB, REST bodies to 4 MiB, and WebSocket messages and frames to 1 MiB. Normalized JSON output remains limited to 2 MiB, and history output remains limited to 2,000 state points. The [camera snapshot contract](camera-snapshot.md) owns its image and transport limits. Component deployment uses its separate one-permit transaction and timeout contract.

The server uses fixed origins and credentials. It disables REST redirects and environment proxies and never returns upstream wrappers or error bodies. Execution actions read and discard bounded upstream results and return only a minimal result. Trace queries return only their canonical projections. Authorized blueprint gets can return bounded semantic YAML. Component deployment returns only bounded operation metadata.

Successful query results return the complete normalized object as serialized JSON text and as the same object in `structuredContent`. Progressive filters keep text and structured content synchronized. Camera results retain their specialized image response, and execution actions retain their minimal acknowledgment response.

Semantic failures use `structuredContent.error` with stable `code`, `message`, and `retryable` fields. Codes are implementation-owned stable values, including validation, authorization, absence, rejection, availability, size, response, and deployment categories. Blueprint and deployment errors follow the same source-free privacy contract. All errors follow the [exposure and data-safety privacy contract](../../architecture/exposure-data-safety.md).
